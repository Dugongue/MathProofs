# BASIS-EXPLICIT UNIVERSALITY OF ORDINARY TENSOR ISOMORPHISM

Informal proof of Grochow–Qiao I, Section 7.1, Open Question 7.4.
November 4, 2026. This is an explicit application of earlier MathProof work; public priority unverified.

THEOREM. Over any field K, isomorphism of basis-explicit linear models of any fixed finite linear signature reduces to ordinary 3-Tensor Isomorphism over K. The reduction is deterministic and polynomial in the explicit input size (field operations in the arbitrary-field model). All source models are allowed, including zero relations, zero functions, and nonconcise tensors. In particular, for every fixed d>=3, this proves universality of ordinary d-Tensor Isomorphism for the corresponding basis-explicit d-way structures in Grochow–Qiao Open Question 7.4.

The proof also handles any fixed tensor-system type of arbitrary finite order with multiple named vector spaces, repeated occurrences of the same named space, and primal/dual factors. Thus it supplies the higher-order analogue of Futorny–Grochow–Sergeichuk's order-at-most-three tensor-system result, as well as the exact single-base-space linear models singled out in the question.

1. Precise source problem
In Grochow–Qiao Definition 7.1 the fixed signature lists positive total arities (r_i,r_i*) for relations and (f_j,f_j*) for functions. A model consists of V, subspaces R_i of V^{tensor r_i} tensor (V*)^{tensor r_i*}, and linear maps F_j from V^{tensor f_j} tensor (V*)^{tensor f_j*} to V. Dense coordinates of a basis of each relation, and the whole coefficient matrix of each function, are supplied. A model isomorphism phi:V->V' applies phi in every primal position and phi^{-T} in every dual position. Write P_w(phi) for the resulting ordered Kronecker action on a given word w of signed factor occurrences. It must satisfy
 P_{w_i}(phi)(R_i)=R_i',
 phi F_j=F_j' P_{u_j}(phi).
In particular the displayed relation bases are presentation data, not individually fixed labelled elements.

More generally the same construction permits a fixed finite list of named base spaces V_s, words in their signed occurrences, and labelled tensors, subspaces, or linear maps between specified words. There is a separate base map phi_s per name; repeated uses of a name share its map. This is the precise higher-order tensor-system setting. The original question is the one-name case.

2. The auxiliary sorts and fixed structural components
A sort means a named vector space with one independent general-linear change of basis at the outset. All auxiliary sorts are named, even when they have equal dimensions. Use the following sorts and tensors in both output systems.

(a) A scalar sort L=K of dimension 1, with fixed multiplication m:L x L->L, m(a,b)=ab. A sort automorphism is multiplication by lambda!=0. The equality h_L m=m(h_L,h_L) gives lambda=lambda^2 by evaluation at 1,1, hence lambda=1. Thus L is pinned pointwise without an order-one tensor or an assumption that GL(1) is trivial.

(b) For each named base V_s add a separately named copy U_s of its dual coordinate space, and fixed evaluation e_s:V_s x U_s->L, e_s(v,u)=u^T v. Once L is fixed, preservation of e_s says u^T h_{U_s}^T h_{V_s} v=u^T v for all u,v. Therefore h_{U_s}=h_{V_s}^{-T}. This couples primal and dual actions over every field, including characteristic two.

(c) For every nonempty signed word needed by a data component, create its prefix spaces W_w. A one-letter word uses the corresponding existing V_s or U_s sort. For a longer word wa, use W_{wa}=W_w tensor W_a with a chosen ordered tensor-product coordinate basis. Include the fixed bilinear map
 mu_{w,a}: W_w x W_a -> W_{wa}, (x,y) -> x tensor y.
One map per distinct prefix suffices. Its coefficient tensor has only zero and one entries. The named sort for each word is distinct from other words' sorts; preserving it does not permit a permutation of positions or of the prescribed names.

All the structural components above are maps bilinear in two inputs. A bilinear map X x Y->Z is naturally represented by its order-three tensor in Z tensor X* tensor Y*. Under sort maps (h_X,h_Y,h_Z), the tensor correspondence is exactly h_Z M=M'(h_X,h_Y), by evaluating on input vectors. Thus these are genuine tensor-system components with the compiler's standard primal/dual convention.

3. Encode the input data without adding spurious restrictions
For relation R_i in W_{w_i} of dimension b_i, add a new sort B_i=K^{b_i}. Let J_i:B_i->W_{w_i} be the matrix whose columns are the supplied basis vectors. Include this linear map as a component. It has order two and can be made order three by tensoring its coefficient tensor with 1 in the pinned sort L. The condition
 h_{W_{w_i}} J_i=J_i' h_{B_i}
allows h_{B_i} to be any invertible basis change. Since the two J_i are injective onto their image, such h_{B_i} exists if and only if h_{W_{w_i}} R_i=R_i'. In that case h_{B_i}=J_i'^{-1} h_{W_{w_i}} J_i, with the inverse taken on the image, is unique. This is equality of subspaces, not one-sided inclusion and not basis-by-basis matching.

For each function F_j:W_{u_j}->V include its coefficient matrix as a linear map, again padded by 1 in L if exactly three factors are required. If the values are supplied on a different explicitly listed domain basis, first multiply the value matrix by the inverse of that basis matrix to obtain coordinates in the standard tensor-product basis; ordinary exact linear algebra takes polynomial time in this explicit dimension. In the multisorted version its output may be any specified word space. The map condition is h_V F_j=F_j' h_{W_{u_j}}. A labelled tensor t in W_w, if present, is encoded by the linear map L->W_w, a->a t, likewise padded. Because L is fixed, this sends t exactly to t', not merely to a proportional vector.

Zero-dimensional relation sorts may be omitted from both systems. If source and target base dimensions or relation dimensions differ, they are immediately nonisomorphic and a fixed NO pair of ordinary tensors is output. Zero base dimensions cause no algebraic problem: a word with a zero-dimensional factor has zero space and its data are uniquely zero; such zero spaces may be omitted, or handled by the existing zero-space-capable compiler. In the one-base source problem n=0 is a trivial YES when both dimensions agree. Zero-valued but positive-size maps are kept as components; the compiler does not need nondegeneracy.

4. Exact witness equivalence
Suppose the original models are isomorphic by phi (or by the family phi_s). On L use the identity. On each U_s use phi_s^{-T}, and on each W_w use the ordered Kronecker product P_w(phi) of the appropriate primal and dual maps. Tensor products preserve the fixed bilinear products, so every structural component is preserved. On each relation sort use the uniquely induced h_{B_i} described above. The original function/tensor conditions then preserve every data component. This produces an isomorphism of the tensor systems.

Conversely, let h be a tensor-system isomorphism. The scalar multiplication fixes L. Evaluation then forces each dual-sort map to be the inverse transpose of its paired primal-sort map. For every prefix product, preservation gives
 h_{W_{wa}}(x tensor y)=h_{W_w}(x) tensor h_{W_a}(y)
for every x,y. Pure tensors span W_{wa}, so this determines the entire linear map h_{W_{wa}} uniquely. Induction on word length yields h_{W_w}=P_w(phi), where phi consists of the maps on the original base sorts. The relation, function and tensor map conditions now recover exactly the source conditions in Sections 1 and 3. Therefore the original models are isomorphic.

No assumption that a general map on a tensor power is a Kronecker product is used. The displayed product components enforce this fact. No basis labels from the relation presentation are silently fixed. In fact the lift of a given source isomorphism to this typed system is unique on all included sorts, although the final ordinary-tensor compiler is used here only for its isomorphism equivalence.

5. Polynomial reduction to ordinary tensors
The tensor-system type, number of factors, number of named base sorts, and number of data components are fixed by the source signature. The construction adds only one scalar sort, the prescribed dual sorts, finitely many prefix sorts, and one relation-basis sort per nonzero relation. In particular the number of components is bounded solely by the signature, even when a relation has a large basis. Let D be the largest input word length, and n the maximum positive base dimension. Every W_w has dimension at most n^D; b_i is at most the dimension of its corresponding word space. The sum of all sort dimensions and the total dense coefficient count are polynomial in n, with exponent depending only on the fixed signature. The structural maps are filled by elementary product-basis index rules, and the data maps copy the supplied coordinates. Thus the first stage is effective, not an oracle.

For explicit input-size accounting, an active one-name model with any function data or any nonzero relation has at least n dense coefficient positions. If it has no functions and all relations zero, equal base dimensions already decide YES; no n-dimensional auxiliary array is needed even if n itself was binary encoded. The analogous multisorted preprocessing drops unused dimensions after comparison, and drops data maps through zero spaces. Every remaining active base dimension is bounded by the size of an explicitly written nonzero-dimensional data array. The output is therefore polynomial in the explicit input length, not merely in a hidden dimension encoded by a short integer.

Use Futorny–Grochow–Sergeichuk, Wildness for tensors, Theorem 1.1, in the explicit algorithmic form of Chen–Grochow–Qiao–Tang–Zhang, arXiv:2306.03135v2, Theorem 4.1 and Appendix B: fixed-type systems of order at most three reduce to ordinary 3-TI. Its potentially exponential dependence on the number of components is constant here because that number depends only on the fixed signature. It preserves and reflects isomorphism over the same arbitrary field. The coefficient arrays of the compiler use the explicit block/gadget operations of that result. FGS Definition 1.2 and Remark 1.1 give the copy-and-constant coordinate form: the added entries are zero or one and input entries occupy designated subarrays. Thus the compiler itself causes no rational coefficient bit growth. For fixed finite fields, or rational entries in the ordinary binary model, the construction has polynomial output size and bit time; arbitrary abstract fields are understood in the field-arithmetic model. There is no call to an isomorphism solver during compilation.

This same final step can reuse our checked MixedTensorCompiler.mixed_ordinary_correct_and_linear: all components have been expressed as three-factor tensors with the intended mixed variance. In the trilinear-form presentation, evaluate each coefficient tensor against the three corresponding dual-view arguments. Since these pairings are nondegenerate and the compiler uses the inverse-transpose action, its form-pullback equivalence is exactly the tensor equivalence (with the common inverse change if the source/target convention is reversed). The checked theorem supplies algebraic correctness and a linear dimension bound in the total named and slot dimensions. No new Lean check or formal bit-time claim is made here.

For an ordinary d-TI target with d>3, append d-3 one-dimensional factors with fixed coordinate 1 to the constructed three-tensors. A d-TI witness may scale these factors, but the product of those nonzero scalars can be absorbed into the first original factor, so the padded equivalence is exactly 3-TI. Conversely a 3-TI witness extends by identities. This proves the required result for every fixed d>=3.

6. Relation to the literature and to SL-TI
The exact source is Grochow–Qiao, Tensor Isomorphism-Completeness, SIAM Journal on Computing (2023), Definition 7.1, Theorem 7.3 and Open Question 7.4. The theorem there covers relation arities <=3 and function arities <=2. Here the higher arity is handled by explicit power sorts and lower-order coherence tensors, then the credited existing compiler. The proof applies to every fixed finite signature, so covers every fixed d-way signature requested by the question, and to the general fixed tensor-system analogue. It is an affirmative complete informal answer in that scope. It is not a claim that FGS's order-three compiler or ordinary tensor-product coherence is new.

Our earlier PRIOR-UNIFORM-PACKING.md, Section 8, already proves the ordinary-TI reduction for explicitly dense higher-order mixed tensor systems, using these prefix-product maps. The checked BalancedOrdinaryReduction project and its MixedTensorCompiler provide another verified algebraic implementation of the low-order terminal compiler, and use product trees for independent leaf factors. Thus the higher-order tensor-system mechanism is prior MathProof work, not a new discovery here. This document makes explicit how the exact Definition 7.1 relation/function interface reduces to that prior theorem: a relation basis is an inclusion with its own free source basis, and a function is a map tensor with the shared action. The result is a documented affirmative corollary answering the named question. Bounded current literature search found no separately stated full later answer to Question 7.4; because this is a short consequence of established machinery, publication priority remains genuinely uncertain. The 2024/2026 classical-group paper supplies the compiler and specific classical-group order reductions, not an independently identified theorem for this complete source-model setting. The 2025 linear-length paper supplies further compiler improvements; those are credited and not rediscovered. The latest commutative-ring sequel (arXiv:2611.00735) was also screened for basis-explicit models and tensor-system universality; no matching result was located there.

This can compile any determinant or other group constraint that is ALREADY expressed as a polynomial-size fixed-order typed tensor system. For example, a supplied explicit volume tensor on a fixed-dimensional marked block restricts that block to SL by its direct top exterior action. It does not by itself provide the missing polynomial-size description of a volume tensor in arbitrary growing dimension. Encoding det(phi)=1 by the full n-fold tensor power or explicit alternating n-tensor has arity n and enormous dense size; fixed-arity polynomiality does not cover that. A small arithmetic circuit computing determinant is not automatically a typed linear isomorphism gadget for unknown basis changes. Hence the unrestricted SL-TI vs TI containment remains separate.
