# Physical Cayley and Berkowitz callbacks in Lean

Lean 4.33 components for Collins–Grochow–Levet–Weiß Question 8.1. The question asks for an actual minimum generating set from a Cayley table in deterministic logarithmic space. The complete search proof remains informal. [Question 8.1](https://arxiv.org/html/2402.00133#S8)

## Cayley connectivity

The Reingold reader answers full, rank-prefix and edge-deleted Cayley queries from the encoded table with a logarithmic live-state bound. The separate physical compiler transports a native CSLib binary multitape execution, its exact output and its logarithmic space bound to the project's tape model. [Reingold reader](Mathproof/MinimumGenerationReingoldNative.lean) · [CSLib compiler](Mathproof/MinimumGenerationCslibLowering.lean)

Given one returned virtual input symbol, a finite controller applies the native instruction and runs the indicated fixed-width head update while preserving the raw input head. Its final configuration is ready for the next callback. [Physical virtual-head step](Mathproof/MinimumGenerationVirtualTapeStep.lean)

A fixed machine seeks the raw table payload and installs all ten comparison banks from live templates, including previously used scratch. The list-free greedy selector returns the next eligible label and preserves the subgroup generated by every prefix. Executing its membership queries and integrating the resulting labels with the full physical Reingold run remain open. [Trial preparation](Mathproof/MinimumGenerationTrialInstall.lean) · [Greedy selector](Mathproof/MinimumGenerationGreedyGenerator.lean)

The positive-only adjacency controller searches with the endpoints in one order, then invokes the supplied reset and searches with them reversed on rejection. Both calls share one workspace bound. The resume and reset contracts require actually reached, halted configurations. [Positive generator stream](Mathproof/MinimumGenerationReingoldPositiveStream.lean)

## Weighted Gram and Berkowitz computation

The exact rank theorem covers every rectangular matrix over a prime field. A finite controller implements the weighted Gram row loop given the actual prepared entry and arithmetic subroutines. It carries one common head bound through every row and leaves protected banks and prior output unchanged. [Exact rank](Mathproof/MinimumGenerationRankPrime.lean) · [Gram row controller](Mathproof/MinimumGenerationRankLiveEntry.lean)

A physical tape substitution runs a binary subroutine on two prepared work banks while the original input head remains parked. The evaluator budget bounds the whole Boolean stack together with one active callback by an explicit multiple of the raw input logarithm when depth and address width are polynomial in the double logarithm. [Tape substitution](Mathproof/MinimumGenerationLocalInput.lean) · [Space budget](Mathproof/MinimumGenerationRankSpace.lean)

Bit-column division by two gives an exact streamed sum of word callbacks with bounded carry. The product routine requests only individual operand bits, has a five-register suspension with an exact binary width, and has a checked request-and-resume cursor. A physical read of a prepared operand supplies the correct reply to that cursor. The polynomial-basis product is a streamed sum followed by one prime-field reduction, and the prime-field routines give exact callback-based Barrett multiplication and modular addition. The complete physical arithmetic and matrix-entry driver still needs an end-to-end execution proof. [Streamed sum](Mathproof/MinimumGenerationRankStreamedSum.lean) · [Physical product call](Mathproof/MinimumGenerationRankProductCallback.lean) · [Prime-field arithmetic](Mathproof/MinimumGenerationRankBerkowitzPrimeWord.lean)
