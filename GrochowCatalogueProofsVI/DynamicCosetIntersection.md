# Dynamic point constraints on two permutation cosets

## GP-0495

Given two cosets of generator-described permutation groups on $n$ points, there is a deterministic quasipolynomial preprocessing pass after which each arriving point-image constraint can be handled in polynomial time. The data structure returns feasibility and, when feasible, a permutation satisfying the entire prefix. It maintains polynomial-size state and also handles a bounded-domain consistent partial map provided one pair at a time. [Babai, quasipolynomial coset intersection](https://people.cs.uchicago.edu/~laci/17groups/version2.1.pdf)

Use left cosets in the notation $uH=\{u\circ h:h\in H\}$. If their intersection is nonempty and $w$ is a common permutation, the intersection is exactly $w(H\cap K)$. Indeed $w^{-1}\circ v$ lies in both groups for every common $v$, and right-composing $w$ by an element of both groups stays in both cosets.

A decision algorithm for coset intersection suffices for the preprocessing. To extract $w$, fix the images of points one at a time in both cosets. Slicing one coset by $x\mapsto y$ either fails an orbit test or produces a left coset of a point stabilizer, so guessing each image and using the decision test runs in $O(n^2)$ calls. To obtain generators of $H\cap K$, let $H_i,K_i$ fix the first $i-1$ points and use Schreier–Sims to obtain generating sets. For each $i$ and possible image $y$ of $i$ find a witness in $H_i\cap K_i$ taking $i$ to $y$, again by the same constrained coset intersection and witness extraction. These witnesses give a left transversal at every level of the stabilizer chain of $H\cap K$. Their union generates it, by reducing the image of each successive point and leaving the earlier points fixed. There are polynomially many queries of quasipolynomial cost. If the initial intersection is empty, every answer is infeasible.

Now let the current feasible set be $wJ$ where $J$ fixes every already constrained source point. On arrival of $x\mapsto y$, find $g\in J$ with $g(x)=w^{-1}(y)$ by orbit computation. If none exists, the current prefix and every extension are infeasible. Otherwise the updated feasible set is exactly $(w\circ g)J_x$, with $J_x$ the point stabilizer. The orbit computation, witness update and strong generators for the new stabilizer take polynomial time in $n$ and the encoded generating data. Keep a polynomial-size strong generating set at every step. This proves the guaranteed update cost without any online coset-intersection calls.
